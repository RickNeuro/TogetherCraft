# TogetherCraft

TogetherCraft — сайт для публичного просмотра страницы проекта и защищённого мониторинга приватного Minecraft Fabric-сервера. В текущей версии уже реализованы рабочие аккаунты в PostgreSQL, заявка на доступ, админ-панель и попытка добавить одобренный Minecraft-ник в whitelist через RCON.

## Что включено в исходники

Код и Docker-конфигурация подготовлены, но в среде, где создавался архив, отсутствовали .NET SDK и Docker. Поэтому реальную компиляцию и запуск необходимо подтвердить первым запуском на Windows/Ubuntu; не считай этот архив уже развёрнутым или runtime-проверенным сервером.

- Главная страница использует **исходное изображение с лисой, присланное автором проекта** (`wwwroot/img/hero-fox.jpg`). Оно показывается целиком, без второго большого логотипа поверх картинки.
- Вентилятор в карточке телеметрии вращается CSS-анимацией. Скорость при этом честно показана как неизвестная, пока датчики не подключены.
- Регистрация сохраняет пользователя и хеш пароля в PostgreSQL. Minecraft-ник обязателен и проверяется по формату Java-ника.
- Новые аккаунты имеют статус `Pending`. Админ создан при первом запуске из переменных окружения.
- В админ-панели кнопка «Одобрить и добавить в whitelist» сначала выполняет `whitelist add <ник>` через RCON и меняет статус аккаунта на `Approved` только после подтверждения Minecraft. Если RCON не настроен или сервер не отвечает, заявка остаётся ожидающей и её можно повторить.
- Обычные пользователи не получают RCON/консоль и не могут выполнять команды управления.
- PostgreSQL хранится в именованном Docker volume; порт базы не опубликован на хост.
- `/healthz` проверяет доступность базы данных.
- Публичный HTTPS предусмотрен через Caddy, но для его включения требуется домен и доступность входящих портов 80/443 либо отдельно настроенный туннель.

## Честные ограничения

Дашборд пока **не получает реальные метрики** CPU, RAM, температуры, оборотов вентиляторов, TPS или числа игроков: поля отображаются как `—`, а не как случайные цифры. Сбор телеметрии с Ubuntu/Fabric/spark — отдельная следующая задача.

Чтобы автоматическое добавление в whitelist работало, нужно включить RCON на Minecraft-сервере и выставить в `.env` пароль совпадающий с `rcon.password` в `server.properties`. Пока этого нет, одобрение безопасно не завершается: аккаунт не получает статус одобренного, а заявка остаётся ожидающей.

## Запуск через Docker (рекомендуемый способ)

Нужен Docker Engine с Docker Compose v2 (на Windows — Docker Desktop).

1. Распакуй проект в отдельную папку.
2. На Ubuntu можешь запустить подготовленный скрипт: `bash scripts/first-start.sh`. Он создаст `.env` с уникальными секретами, покажет одноразово созданный пароль администратора и соберёт контейнеры.
3. Если предпочитаешь ручную настройку, скопируй `.env.example` в `.env` (PowerShell: `Copy-Item .env.example .env`; Ubuntu: `cp .env.example .env`), замени оба `CHANGE_ME...` разными случайными секретами и выполни `docker compose up --build -d`.
4. Открой `http://127.0.0.1:8080`.
5. Войди логином `ADMIN_USERNAME`, пароль — `ADMIN_PASSWORD` из локального `.env`. Если использовал скрипт, он напечатает созданный пароль один раз.

Пересобрать только веб-контейнер после обновления кода можно одной командой:

```bash
bash scripts/rebuild.sh
```

Скрипт пересобирает образ, пересоздаёт `togethercraft-web` и показывает состояние контейнеров. Он не удаляет базу данных.

Полезные команды:

```bash
docker compose ps
docker compose logs -f togethercraft-web
docker compose logs -f postgres
docker compose down
```

`docker compose down` не удаляет данные PostgreSQL. Не используй `docker compose down -v`, если не хочешь удалить том базы данных.

### Где лежит база

PostgreSQL работает в контейнере `togethercraft-postgres`, а данные хранятся в Docker volume `postgres-data`. Контейнер базы не публикует порт на хост и доступен приложению по внутренней сети Docker.

## Подготовка RCON для whitelist

Для реального ограничения доступа Minecraft настрой `white-list=true` в том же `server.properties`, который использует работающий Fabric-сервер. Прежде чем включать RCON, не делай настройку наугад.

Не включай RCON вслепую на работающем сервере. Сначала найди именно тот `server.properties`, который использует текущий Fabric-сервер. Инструкция по настройке и проверке находится в [`docs/WHITELIST.md`](docs/WHITELIST.md). Никогда не открывай порт RCON на роутере и не коммить `.env`.

## Публикация в интернет через HTTPS

1. Нужен домен, у которого DNS указывает на сервер, и возможность принять входящие подключения на портах 80 и 443. Если провайдерский NAT это блокирует, потребуется подходящий внешний туннель.
2. Укажи свой реальный домен в `PUBLIC_DOMAIN` в `.env`.
3. На Ubuntu запусти:

   ```bash
   docker compose --profile public up --build -d
   ```

   Caddy получит TLS-сертификат и направит HTTPS-трафик в приложение. Не выставляй PostgreSQL или порт RCON наружу.

Пока домен/туннель не настроен, сайт доступен только локально через `http://127.0.0.1:8080` — это намеренно безопасное поведение, а не публичная публикация.

## Работа из Visual Studio 2022

Открой `TogetherCraft.sln`. Для тестирования пользовательских форм удобнее запустить приложение вместе с PostgreSQL через Docker Compose. При запуске только через F5 без доступной базы главная страница откроется, но регистрация/вход будут сообщать, что PostgreSQL недоступен.

Проект сейчас на .NET 8 для совместимости с распространёнными установками Visual Studio 2022. До длительной публичной эксплуатации нужно обновить проект до поддерживаемого .NET и проверенную версию пакета Npgsql. Microsoft указывает окончание поддержки .NET 8 на 10 ноября 2026 года: https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core

## Безопасность

- `.env` не должен попадать в GitHub.
- Пароли пользователей хранятся только как salted password hashes.
- Первый администратор создаётся через переменные окружения при инициализации БД.
- PostgreSQL не опубликован наружу.
- RCON не опубликован наружу и вызывается только серверной частью после нажатия администратора.
- Для реального интернет-доступа следует включить HTTPS через Caddy или проверенный туннель и не перенаправлять порт RCON.

## Системные метрики Ubuntu

В `compose.yaml` Prometheus и Node Exporter работают как отдельные контейнеры. Порты их веб-интерфейсов привязаны к `127.0.0.1`, PostgreSQL остаётся во внутренней сети Docker, а API TogetherCraft с метриками требует одобренную авторизацию. Веб-страница запрашивает `/api/metrics` раз в 10 секунд.

- CPU, RAM и системный диск читаются из Node Exporter.
- Температура CPU и обороты вентилятора появятся только при наличии соответствующих показаний `hwmon` в Linux.
- Данные Minecraft (TPS, MSPT, игроки и онлайн/оффлайн) подключаются отдельно, после подтверждения работы системных метрик.

После обновления исходников используй `docker compose up --build -d`. Не удаляй Docker volumes и не выполняй `docker compose down -v`: в PostgreSQL хранятся аккаунты.


## Actual hardware telemetry patch (2026-10-17)

PrometheusMetricsService queries the CPU temperature sensor by the PCI `chip` label reported by node_exporter, rather than searching for the literal name `k10temp`. Fan channels `fan1` and `fan3` are queried separately. The dashboard displays both values and animates the fan rotor only when a positive live FAN1 RPM value is available.
